# web-fast-crawl

A bounded asynchronous crawler for HTML, JavaScript applications, JSON APIs, and
commerce catalogs. It produces a JSON report containing captured structured data,
product observations, and an indexed semantic graph. `web-fast-core` remains the
independent, side-effect-free HTML parser; this crate owns networking and optional
browser execution. It has a Rust API and CLI, with no Python/Node binding or Flight
service in the release matrix.

## Run

Static HTML, JSON-LD, embedded application JSON, and linked JSON endpoints work
without a browser:

```sh
cargo run -p web-fast-crawl --locked -- https://example.com/ \
  --max-pages 100 --max-depth 3 --focus products --output crawl.json
```

For JavaScript execution, install Node and the pinned Playwright dependency. Use
an installed Chrome with the default channel, or install Playwright Chromium:

```sh
npm ci --ignore-scripts --prefix web-fast-crawl/browser
npm exec --prefix web-fast-crawl/browser -- playwright install chromium
cargo run -p web-fast-crawl --locked -- https://example.com/ \
  --render auto --browser-channel chromium --scroll-steps 2 \
  --resource-origin https://cdn.example.com \
  --resource-origin https://api.example.com --output crawl.json
```

Browser-enabled crawls no longer advertise `web-fast-crawl/0.1`. Before the first
HTTP request, the sidecar reads `navigator.userAgent` from the selected browser.
That same value is used by the HTTP bridge and page JavaScript. Headless browsers
may naturally include `HeadlessChrome`; `--headed` selects a visible browser and
its native non-headless identity. No browser version or platform is fabricated.
The probe uses a local blank page and shares the crawl deadline. Browser startup
must succeed even if `auto` later finds static extraction sufficient.

`--user-agent 'Your explicit value'` / `CrawlOptions.user_agent` overrides the
identity consistently, with header validation. HTTP-only crawls omit User-Agent
by default and do not require Node/browser startup. The report's `user_agent`
records the resolved value. The independent `agent` option still selects robots
rules and agent-scoped indexing directives; it is not automatically sent in headers.
These changes do not import the user's authenticated browser session or change the
HTTP bridge's transport. An account-verification redirect can still occur.

Use `--render always` for pages whose static content is substantial but incomplete.
`auto` renders only pages with scripts, fewer than 200 extracted text bytes, and
no normalized products. Rendering defaults to `disabled`. `--browser-executable`
selects an explicit Chromium binary; `--browser-runner` selects the packaged
`browser/runner.mjs` when moving a compiled binary away from its build checkout.
Keep the runner beside its installed npm dependencies. Rendering starts a fresh
browser per page and adds startup cost; static requests use a pooled HTTP client.

`--allow-origin` extends page discovery. `--resource-origin` only permits browser
subresources/API requests and does **not** extend top-level navigation or page
crawl scope. All seed origins are allowed. URL fragments are removed for fetching;
query order and tracking parameters are retained because they can affect content.
Fetch URLs must also be valid RDF IRIs. Browser-valid link/canonical strings that
cannot be RDF IRIs remain text evidence, with a diagnostic, instead of aborting
the page graph.
Private/loopback targets require `--allow-private-networks` (also used by fixtures).

## Rust API

```rust,no_run
use web_fast_crawl::{CrawlOptions, Crawler};
use web_fast_crawl::browser::RenderMode;

# async fn example() -> Result<(), Box<dyn std::error::Error>> {
let mut options = CrawlOptions::default();
options.browser.mode = RenderMode::Auto;
options.focus_terms = vec!["products".into(), "specifications".into()];
let report = Crawler::new(options)?
    .crawl(&["https://example.com/".into()]).await?;
println!("{} pages: {}", report.pages.len(), report.stop_reason);
let json = serde_json::to_vec(&report)?;
# Ok(())
# }
```

All policies are available through `CrawlOptions`; the CLI exposes common options.
A report can be partial: inspect `stop_reason` and each page's `diagnostics`.
`complete` means the admitted frontier was exhausted, not that every resource or
extraction succeeded. Failures retain operational evidence without raw error
payloads. Full parsed documents require `retain_documents` / `--retain-documents`.

## Structured JSON and commerce

Sources include JSON HTTP responses, JSON-LD, `application/json` script elements,
strict JSON assignments to common hydration globals, browser runtime state, and
successful JSON responses generated by page JavaScript. The renderer also captures
Next.js flight arrays as raw state when available. Nuxt devalue and React Server
Component protocols are retained as payloads; they are not fully decoded into
framework-specific application models. Static assignment extraction does not
execute JavaScript expressions.

Each source records its kind, URL, locator, JSON value, and a SHA-256 of the
serialized parsed value. This digest is distinct from the original HTTP-byte
`source_sha256` and rendered-DOM `rendered_sha256`. JSON parsing preserves structure
and string values, not original whitespace, duplicate keys, or numeric spelling.

Commerce normalization finds declared Schema.org products and recognizable product
shapes within hydration/API JSON, including GraphQL connections. Results preserve:

- Name, description, condition, SKU, GTIN, brand, product URL, image URLs, and external identifiers.
- Offer prices, currency, payment context, explicit stock quantity, availability, seller, and URL.
- Up to 100 variants per product with their own identifiers, options, and prices.
- Source index and JSON pointer for every product/pagination observation.
- Explicit `declared_type` or `field_shape` extraction basis.

Price strings stay strings. Currency and minor-unit scaling are never inferred:
unknown price units are `unspecified`, while declared Schema.org prices and the
explicit Mercado Livre Brazil and Amazon HTML adapters use major units. Raw source JSON remains available when normalization is incomplete. These
are observations, not guaranteed catalog identities; unrelated offers are not
merged merely because their names match. Microdata and RDFa extraction are not
implemented.

For Mercado Livre Brazil, an HTML-card adapter extracts `.poly-card` records when
these are present in a permitted page. It reads the current amount separately from
crossed-out prices and installments, validates Brazilian digit grouping, and maps
the explicit accessible currency name `real`/`reais` to BRL. Payment/price text is
retained in `price_context`. These sources are labeled `html_product_cards`, with
`html_card` basis and CSS selector/card ordinal evidence; their JSON is derived
from HTML, not falsely attributed to an API. They share JSON/product budgets.
The adapter makes a second bounded-input DOM parse and currently requires UTF-8.
Descriptions and availability are left absent when cards do not provide them;
a displayed card does not prove stock or a universally applicable purchase price.
Multiple cards for the same catalog product remain separate offer observations.

For `amazon.com`, the detail adapter captures title, ASIN, main image, and an
excerpt of up to 160 words from feature bullets. Derived sources use
`html_product_detail` and `html_detail` basis, with selector evidence and explicit
description truncation. Prices and currency come from explicit buy-box inputs;
stock comes from the same offer, excluding scripts and inert content. New-item
accordion offers and featured single-offer layouts are supported. Resale rows do
not supply missing new-item prices; condition is not inferred for single offers.
Missing fields remain absent. These selectors are site-specific and can drift.
Responses carrying `x-amzn-waf-action: challenge` or `captcha`, including HTTP 202,
produce an access-challenge diagnostic, without indexing or retrying the payload.

JSON descriptions retain their provided text/markup. Marketplace-shaped API fields
such as `currency_id`, `seller_id`, `permalink`, `pictures`, and `available_quantity`
are normalized when present. API responses containing only a separate description
are not silently joined to unrelated products. This is extraction support, not an
authenticated Mercado Livre API client.

Live detail requests may redirect to account verification. The report distinguishes
`redirect destination is disallowed by robots policy` from a restriction on the
original URL; neither is reported as successful product-detail extraction.

The crawler follows in-scope `rel=next`, JSON alternate links, and explicit JSON
next-page URLs. GraphQL `hasNextPage`/`endCursor` are retained as hints; it does not
invent subsequent GraphQL requests from opaque cursors.

## Optional O-Laya classification

The example postprocessor uses the actual local
[O-Laya Node runtime](https://github.com/josaum/olaya/tree/main/packages/olaya-node)
to classify captured product text against a supplied ontology. It preserves prices,
descriptions, missing fields, source pointers, HTML extraction evidence, and the
inferred ancestor path separately. No model download or external API is used by
this lexical runtime. The example taxonomy is a small custom commerce vocabulary,
not GS1 certification or a comprehensive product catalog.

```sh
node web-fast-crawl/examples/olaya-products.mjs \
  --input crawl.json --output classified-products.json \
  --runtime /path/to/olaya/packages/olaya-node/dist/index.mjs
# Optional: --ontology taxonomy.json --minimum-confidence 0.2
OLAYA_RUNTIME=/path/to/olaya/packages/olaya-node/dist/index.mjs \
  node --test web-fast-crawl/examples/olaya-products.test.mjs
```

The output includes input, ontology, and runtime SHA-256 digests. Root-only,
inconsistent, and below-threshold decisions are marked `needs_review`. The default
threshold is illustrative, not empirically calibrated. Confidence reflects lexical
concentration; ontology consistency does not verify source claims or classification
accuracy. `noindex` pages are excluded. The optional integration test needs the
local runtime and otherwise explicitly skips; Rust CI does not install O-Laya.

## Modern websites

The optional Playwright sidecar executes scripts, waits for bounded network/DOM
quiet periods, performs a configured number of scrolls, and captures the resulting
DOM and open shadow roots. Closed shadow roots and embedded frame documents are
not flattened. Stylesheets may load, but text extraction still follows the static
parser's DOM rules rather than computed CSS visibility.

Browser HTTP requests pass through the Rust bridge, which applies origin/IP scope,
robots rules, pacing, concurrency, request limits, and decoded response-byte limits.
The initial HTML is replayed instead of downloaded twice. Image, media, and font
downloads are skipped by default. Additional CDN/API origins need explicit scope.

GraphQL POSTs require an operation document parsed as a query. Mutations,
subscriptions, and ambiguous multi-operation requests are blocked. Unknown
persisted-query hashes receive a synthetic `PersistedQueryNotFound` response so
compatible clients can submit the full document for validation. Other POSTs require
exact URLs in `browser.read_only_post_urls`, explicitly classified by the caller.
No forms, checkout controls, or authentication prompts are clicked. The browser
uses a fresh context without an existing profile; cookies and Set-Cookie are not
forwarded by the bridge. Session-dependent sites may consequently fail.

Service workers, WebSockets, WebRTC, and WebTransport are disabled. Rendering is
not a process-level network/memory sandbox: use OS/container isolation for untrusted
sites when that boundary is required. There is no CAPTCHA bypass or stealth mode.
Rendering failures retain the static result and a diagnostic. A timeout/quiet
period is not proof that an application's content is complete.

## Semantic graph

JSON-LD is expanded to RDF with an offline document loader. The bundled Schema.org
context and caller-supplied context snapshots are trusted inputs; unknown remote
contexts reject that script without fetching it. Typed/language literals, RDF
lists, scoped blank nodes, named graphs, and page provenance survive projection.
Unsupported RDF 1.2 directional/triple terms reject the whole affected script.
The graph also records page metadata, headings, block structure, links, canonical
hints, redirects, and byte-identical content observations. Canonical and duplicate
hints never merge page identities automatically.

Normalized commerce shapes become `urn:web-fast:ProductObservation` nodes with
source links and pointers. Heuristics do not assert an authoritative Schema.org
Product type; declared JSON-LD is projected separately through the RDF parser.

`GraphBuilder` interns terms and deduplicates statements including source/named
graph. `finish()` builds CSR outgoing, incoming, and predicate indexes. `matching`
uses the smallest applicable index; `reachable` provides bounded graph traversal;
`page_rank` ranks resource links with dangling-mass redistribution and duplicate
provenance edges removed. The JSON report stores terms and indexed edges, with
source and named-graph identifiers. In-process indexes are not serialized.

The graph benchmark compares a full scan and indexed lookup on the same 100,000-edge
chain. Local Apple Silicon release measurements were 22.4 µs vs 17.2 ns per query;
this is a small adjacency-query microbenchmark, not end-to-end crawl throughput.

## Policies and limits

| Default | Value |
| --- | ---: |
| Page attempts / depth / frontier URLs | 100 / 3 / 10,000 |
| HTTP concurrency / per-origin concurrency | 4 / 2 |
| Minimum interval between origin request starts | 200 ms |
| Total HTTP attempts, including robots/retries/resources | 1,000 |
| Total decoded response bytes / one response | 64 MiB / 4 MiB |
| Crawl network deadline / HTTP attempt timeout | 300 s / 30 s |
| Sitemaps / redirects / extra retries | 32 / 8 / 2 |
| Browser deadline / resources / scroll steps per page | 20 s / 64 / 2 |
| Captured JSON sources / bytes per page | 64 / 8 MiB |
| JSON normalization nodes / depth / products per page | 100,000 / 64 / 1,000 |
| Graph terms / statements / term bytes | 1,000,000 / 2,000,000 / 128 MiB |

The frontier prioritizes lower depth, then focus-term matches, then admission order.
Concurrent HTTP batches are consumed in admission order. Browser response order and
live website content can vary. Robots are cached per origin for a crawl (maximum
24 hours), capped at 512 KiB, with unavailable robots failing closed. 401/403/429
also deny crawling; other client errors follow the unavailable-file policy.
Transient failures use bounded retries; `Retry-After` delays the origin even when
it exceeds the retry allowance. No ambient HTTP proxy is used; the connection's
DNS results are checked against address policy.

HTML robots metadata and scoped `X-Robots-Tag` restrictions combine restrictively.
`noindex` drops page content, structured data, title, and semantic projection;
`nofollow` prevents page discovery. Individual nofollow links are skipped. API JSON
with `X-Robots-Tag: noindex` is excluded from direct capture; this is not information-
flow tracking of data that page JavaScript later transforms. Operational URL/status/
hash evidence can remain.

Sitemap indexes are bounded and cycle-deduplicated. DTDs are rejected; HTTP gzip,
Brotli, and deflate responses are bounded after decoding. Standalone `.xml.gz`
sitemap files without HTTP content encoding are not unpacked. Limits are enforced
at documented parsing/capture stages, not as a strict resident-memory cap. Synchronous
parse work and browser cleanup can extend elapsed time beyond the network deadline.
There is no distributed frontier, resumable checkpoint, or persistent HTTP cache.

## Verification and licensing

```sh
cargo test -p web-fast-core -p web-fast-crawl --locked
cargo clippy -p web-fast-crawl --all-targets --locked -- -D warnings
cargo bench -p web-fast-crawl --bench graph_paths --locked
# After the npm/browser installation above:
cargo test -p web-fast-crawl --test browser_e2e --locked -- --ignored
```

HTTP integration tests use local servers, including redirects, pacing, Retry-After,
compression, robots, budgets, sitemaps, and JSON pagination. Graph tests cover RDF
semantics, offline contexts, provenance, indexing, and ranking. Browser tests execute
real Chromium/Chrome with local JS/API fixtures; CI installs pinned Playwright and
Chromium. They need no external commerce service.
